# 飞书通讯录同步与 OAuth 登录

## 目标架构

系统只使用一个飞书企业自建应用承载三项能力：通讯录全量同步、OAuth 登录和通知投递。`appSecret` 只以 AES-256-GCM 密文保存在 `IntegrationConfig.encryptedConfig`；tenant token、user token、OAuth code、state 和登录 ticket 均不以明文持久化。

通讯录同步以配置的根部门为边界，读取根部门、全部子部门和各部门直属用户，保存姓名、手机号、邮箱、头像、`user_id/open_id/union_id`、部门成员关系和状态。同步按用户独立事务执行，单个用户失败只增加 `failed`，不会回滚整批；结果固定输出 `total/added/updated/disabled/skipped/failed/departments`。

当根部门配置为飞书结构性根节点 `0` 时，飞书可能不返回普通部门具备的名称或 `open_department_id`。系统在接口响应成功后以稳定 ID `0` 和名称“企业根部门”建立本地根节点，再同步其子部门；非根部门仍严格校验飞书返回的 ID 和名称。

通知测试优先使用后台从已同步通讯录中明确选择的系统用户。候选接口只返回当前飞书集成下系统账号启用、外部身份启用、未停用且存在 `open_id` 的用户；发送前后端会再次按系统用户 ID 校验同一条件并读取唯一 `open_id`，防止向已离职、停用或身份漂移的用户发送。历史配置仍兼容直接填写 `open_id`；未选择同步用户或填写 `open_id` 时，也可配置用户登录邮箱，由后端通过飞书 `contact/v3/users/batch_get_id` 实时解析该应用下唯一、在职且已激活的 `open_id`。收件人配置、邮箱和解析结果均不写入仓库或发布清单。

OAuth 登录只接受已经同步且唯一绑定的启用用户。浏览器 state 有效期 5 分钟，回调后立即原子消费；登录 ticket 有效期 60 秒，也只能消费一次。飞书 token 仅用于服务端读取当前身份，系统最终仍签发自己的短期 Access Token 和 HttpOnly Refresh Cookie。

飞书客户端内打开平台且当前没有系统会话时，前端根据飞书客户端容器标识在当前标签页自动发起一次现有 OAuth。飞书授权页在客户端内复用当前飞书身份免确认回调，后续 state、唯一身份绑定、启用状态、ticket、权限解析和 Refresh Session 校验与普通飞书 OAuth 完全一致。自动尝试失败后保留普通账号登录和手动飞书登录入口；同一标签页不重复自动跳转，确保异常回调和主动退出不会形成循环。

前端使用 Hash 路由。飞书只回调后端登记地址 `/api/v1/auth/feishu/callback`；后端校验并消费 state 后，必须跳转到 `/#/login/feishu/callback?ticket=...`，由前端消费一次性 ticket。普通路径 `/login/feishu/callback?ticket=...` 无法命中 Hash 路由，属于错误契约。

## 飞书开放平台配置

1. 在飞书开放平台创建企业自建应用，并限制应用可用范围。
2. 在“权限管理”申请并发布通讯录只读权限。按飞书后台当前中文名称至少包含：获取通讯录基本信息、获取通讯录部门组织架构信息、获取用户基本信息、获取用户组织架构信息、获取用户 user ID；若要同步手机号和邮箱，再申请获取用户手机号、获取用户邮箱信息。
3. 在通讯录“数据权限”中将范围设为允许同步的根部门及其子部门；若配置根部门 `0`，必须选择“全部成员”。仅添加 API 权限而未扩大数据权限时，连接测试仍可能成功，但通讯录同步会被飞书拒绝。
4. 启用机器人能力并申请 `im:message:send_as_bot`；通知测试接收人必须位于机器人的可用范围内。
5. 启用网页应用/OAuth，并在应用的“安全设置 → 重定向 URL”中登记精确回调地址。测试环境为：

   ```text
   https://1.117.73.165/api/v1/auth/feishu/callback
   ```

   飞书后台登记值、系统设置中的 `oauthRedirectUri` 和浏览器发起授权时的 `redirect_uri` 必须逐字一致。不要登记前端内部落点 `/login/feishu/callback`。飞书错误码 `20029` 表示当前授权请求的 `redirect_uri` 未被精确登记；修改后必须保存并发布应用版本。生产环境必须填写生产 HTTPS 地址，禁止复用测试回调。
6. 发布新应用版本并由企业管理员审批新增权限和数据范围。未发布、未审批或超出应用/机器人可用范围的成员不能登录或接收测试消息。

## 系统配置与首次同步

使用唯一管理员登录“系统设置 → 接口集成 → 飞书”，填写：

- App ID；
- App Secret；
- 通讯录根部门 ID，完整企业同步填 `0`；
- OAuth 回调地址；
- 通知测试接收人：优先从“测试消息接收人（同步用户）”中选择已经同步的真实成员；仅兼容历史配置时才直接填写 `open_id`（`ou_...`）。不启用通知验收时才可留空。

页面会按当前访问地址生成建议回调地址，可直接填入或复制到飞书开放平台。“机器人 Webhook”、`Verification Token` 和 `Encrypt Key` 不属于当前通讯录、OAuth 或应用消息契约，后台不再展示这些无效输入。启用配置前必须同时具备 App ID、App Secret 和 HTTPS 回调地址；App Secret 保存后仅显示掩码。

保存并启用后，依次执行“测试连接”和“同步通讯录”。首次同步完成后检查新增、更新、停用、跳过、失败和部门数量；`failed > 0` 时先处理失败项再开放登录。同步成功前，飞书用户没有 `ExternalIdentity`，OAuth 登录会按 fail-closed 拒绝。

填写测试接收人的 `open_id` 后继续执行“测试通知”。三项验收顺序固定为：连接测试成功 → 通讯录同步 `failed=0` → 测试通知成功 → 分别从普通浏览器手动发起飞书 OAuth、从飞书客户端打开网页应用并完成一次真实免登回调。同步和测试结果均记录在同页“同步日志”，不会记录 Secret 或访问 Token。

## 权限与停用行为

同步只维护用户基础资料、飞书身份和组织成员关系，不自动授予业务角色或用户显式权限。权限解析顺序为：超级管理员旁路、用户显式覆盖、用户直接角色、直属组织、逐级上级组织、`dashboard:view` 最小权限；同一组织深度出现冲突时禁止优先。

飞书停用、冻结、离职或从同步范围消失时，系统停用由飞书自动创建的普通用户、增加权限版本并撤销全部未撤销 Refresh Session。`SUPER_ADMIN` 不会被同步降权或停用。人工绑定的账号不会仅因飞书身份消失而自动停用，但该飞书身份本身会失效并禁止 OAuth 登录。

## 故障排查

- OAuth 回调失败：核对 HTTPS 证书、回调地址精确匹配、应用版本是否发布，以及 state 是否已过期或重复使用。错误码 `20029` 时，在飞书开放平台登记 `https://1.117.73.165/api/v1/auth/feishu/callback`，不要填写 `/login/feishu/callback`，保存并发布后重新从系统登录页发起授权。
- `FEISHU_CONTACT_API_SCOPE_REQUIRED`（飞书业务码 `99991672`）：应用版本缺少当前 Contact V3 接口所需的 API 权限；补齐权限、发布新版本并完成管理员审批。
- `FEISHU_CONTACT_DATA_SCOPE_REQUIRED`（飞书业务码 `41050`、`40004` 或无业务码的 HTTP 403）：应用有调用权限，但目标用户或部门不在通讯录数据权限范围；根部门 `0` 必须选择“全部成员”，然后发布新版本并完成管理员审批。
- `FEISHU_CONTACT_SCOPE_REQUIRED`：旧 Release 产生的兼容诊断；同时核对 API 权限和通讯录数据权限，新 Release 会返回上面两个精确诊断之一。
- 通知测试提示缺少接收人：在系统飞书配置中从同步用户下拉框选择真实成员并保存；不要使用不属于当前企业租户的个人邮箱。
- `FEISHU_MESSAGE_SCOPE_REQUIRED` 或通知被飞书拒绝：确认机器人能力、`im:message:send_as_bot`、应用已发布，以及接收人在机器人可用范围内。
- 用户无法登录：先确认最近一次同步中该身份唯一、启用，且系统用户未停用或删除。
- Secret 无法解密：核对服务器 `INTEGRATION_SECRET_ENCRYPTION_KEY` 是否保持同一 32 字节 Base64 值；不得通过重新填写日志或明文数据库字段绕过。
- 网络/限流：同步日志只记录稳定错误码，不记录 token、secret 或飞书原始敏感响应；稍后由管理员重新触发全量同步。
